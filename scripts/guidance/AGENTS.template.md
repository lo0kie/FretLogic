**编号规则：每份文件各自从「一」起**
—— 编号只在**文件内**唯一，跨文件必然重复。因此所有交叉引用一律写成**「文件名 + 文件内编号」**（如
`02-protected-zones.md` 的「一、稳定保护区」），**严禁**再使用 `§七`、`第七节`、`4.0 / 4.1 / 4.2`
这类全局节号：它们既不唯一，也会在文件被拆分或合并后指向错误的位置。

**这条规则不限于 `rules/`
内部**：仓库里任何位置引用准则时（源码注释、脚本、配置文件、文档）都必须用同一套写法。此前本仓库有一批 `.ts` / `.mjs`
注释引用 `AGENTS §3` / `§4.2` / `§5` / `第七节 2`
之类的全局编号，编号一改就全部变成死引用，已一次性同步为文件名引用 —— 新增引用照此办理，不要图短写回全局节号。

唯一例外是 `changelog/` 下**已提交的历史片段**：按 `04-changelog-fragment-zones.md`
的「一」它们属冻结区、只读，其中出现旧编号属历史记录，不是活引用，**不要去"修正"**。

三部分并列生效，冲突时以**更具体、更靠后写入的具体任务指令**为准；但 `02-protected-zones.md`（稳定保护区）与
`07-loop-limits-and-circuit-breaker.md`
的「五、覆盖机制」所保留的两类红线不接受任务级覆盖；上面那节红线摘要里的三条同样不接受任务级覆盖。

## 注入通道、强制预读与维护口径（不要改回去）

本文件与 `.codebuddy/rules/` 分属**两条独立通道**，一条有上限、一条没有：

| 通道                                                                    | 自动注入的内容                                  | 字符上限            |
| ----------------------------------------------------------------------- | ----------------------------------------------- | ------------------- |
| `.codebuddy/rules/`（宿主 rules 通道）                                  | `rules/` 的**逐字节副本**（{{RULES_COUNT}} 份） | 无，整目录全收      |
| guidance 链（`CODEBUDDY.md` → `.codebuddy/CODEBUDDY.md` → `AGENTS.md`） | 本文件（总纲 + 正文全文）                       | **8000 字符硬上限** |

**正文的唯一源头是根级 `rules/`** —— 两层出口都是它的产物：本文件由 `scripts/build-guidance.mjs` 把 {{RULES_COUNT}}
份正文按序号拼接（总纲段来自 `scripts/guidance/AGENTS.template.md`）， `.codebuddy/rules/` 则是同一批文件的逐字节复制。

**强制预读**：本文件被截断是常态、不是异常。正文合计 {{RULES_CHARS}} 字符，远超 guidance 链的 8000 上限 —— 末尾出现
`[...too long, omitted...]` 就说明**下半部分根本没进上下文**。因此：

**动手改任何代码、跑任何命令之前，若上下文中没有见到全部 {{RULES_COUNT}} 份正文，必须先用 Read 读取根级 `rules/` 下全部
`.md`。**

即便规则到了，也不要假定它一定被执行；以下情况会让注入整条失效：

- `mode === "quick"`（快速问答）时 `ProjectRulesSection.shouldApply` 整段跳过；
- `_meta.isClearSession === true` 时 compose 层直接早退，本轮不注入任何 section；
- 注入只发生在首条 / 恢复消息，之后由 `alreadyInjectedUserContext` 门控不再重复 —— 上下文被压缩后可能一并丢失；
- **注入是快照**：对规则文件的编辑只影响**之后**新建的会话。会话中途改规则，手上的理解与磁盘上的副本立刻分叉 —— 改完必须把改动的文件重读一遍。**写了什么不算数，注入进去的是编辑前的版本。**
